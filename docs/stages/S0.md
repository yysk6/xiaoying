## 干净安装与wheel验证

实际执行：

```powershell
.\.venv\Scripts\python.exe -m pip download --only-binary=:all: -r requirements-dev.lock -d work/s0-wheelhouse
.\.venv\Scripts\python.exe scripts/verify_s0.py --wheelhouse work/s0-wheelhouse
```

首次下载使用公开PyPI，随后的重建使用本地wheelhouse、`--no-index --no-deps`：

1. 创建全新`work/s0-clean`，从运行锁安装依赖。
2. 安装正式wheel，运行依赖检查通过。
3. 从仓库外cwd以`python -I`导入，断言模块实际位于新环境site-packages。
4. 从开发锁安装其余依赖，再次pip check通过。
5. 关闭pytest的src路径注入，以importlib模式对正式wheel运行同样四项测试：**4 passed**。

脚本移除Codex、模型、LangSmith等专用环境变量及PYTHONPATH/PYTHONHOME。使用普通Python工具链；没有Codex运行时或插件依赖。第二次测试不是新增四项用例，独立测试总数仍为4。

证据：[clean-install.json](../../examples/tests/stages/S0/clean-install.json)、[完整命令与输出](../../examples/tests/stages/S0/clean-install.txt)、[clean-junit.xml](../../examples/tests/stages/S0/clean-junit.xml)、[环境版本](../../examples/tests/stages/S0/environment.json)。

复核时先按README安装/构建，再运行`python scripts/verify_s0.py --venv work/s0-review`；若需全程离线增加`--wheelhouse work/s0-wheelhouse`。目标路径须是新路径，脚本不自动删除已有环境。
