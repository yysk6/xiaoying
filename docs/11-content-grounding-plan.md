## 当前缺口与目标

`domain.validate_script`检查source_ids、固定禁用语和无依据百分比；`tools._generate`在这些检查后直接缓存成功脚本。SCRIPT提示已要求遵循素材，但实际脚本仍含一键、几秒钟、瞬间生成和效率翻倍。来源ID正确只说明引用了哪份素材，不证明所有句子受支持。

本项目以选中素材facts为产品事实依据。M01仅支持自动生成字幕、生成文本可编辑。没有依据的操作步骤、速度、准确度、量化效果等不能作为确定事实写入方案；无依据不等于已证明现实为假，处理应是删除、改写或明确资料不足，不能为通过评测补造素材事实。

目标：生成脚本→结构及确定性规则校验→事实支持性审核→合格产物→估算/保存。未审核、审核失败或审核不可用均不能提升为成功脚本。保留创意表达和行动邀请，但不能把产品承诺归为创意来绕过审核。

## 推荐的最小修改

1. **明确生成约束。** 升级script提示，列出允许使用的事实和常见越界类别：未给出的操作次数/界面步骤、速度、准确率、比较优势和效果数字。素材、主题和创意简述均是数据。标题、开头、正文、CTA四个字段都受约束；不把此次失败词清单当完整解决方案。
2. **保留确定性校验，增加独立语义审核。** 新增可注入的审核方法，复用官方DeepSeek HTTP与Pydantic。审核只接收选中素材facts和实际四字段文本，不接收生成者的自评/推理。模型按程序划定的字段/片段ID逐项返回supported、unsupported、uncertain或nonfactual，以及可核对的事实引用和简短依据。程序检查覆盖完整、ID/引用有效；漏项、非法JSON、uncertain都不能通过。事实引用有效仍不等于自动证明语义蕴含，须用独立标注样本验证审核器。
3. **接入真实状态。** 只有审核通过才写入可用script_artifacts。失败返回建议新增的SCRIPT_UNGROUNDED，包含字段、原文片段、问题类别和可公开依据；检索/候选成功结果保留。由planner观察后决定修订brief、再生成或停止，调度器不悄悄改写文本、不自动循环重试。初次加一次修正作为同参数生成上限，继续受既有32次模型/24次动作/4候选约束。
4. **保存前核对审核绑定。** 结论绑定脚本全文哈希、素材内容哈希及审核策略版本；未审、失败、内容变更或绑定失效均拒绝保存。审核网络/协议故障与内容不支持分开记，不回退为通过。旧失败attempt不因后续成功改写。
5. **版本与用量。** 新审核HTTP必须计入真实业务模型请求/usage与32次上限，不能藏在生成内部漏计。升级script/审核提示与manifest/缓存依赖；旧缓存不能自动获得新审核资格。旧方案及原失败报告保留为历史，不能追溯冒记为已审合格。现行真实资料/模型/提示兼容性检查仍生效。

外部生成与审核可使用同一官方模型的分离请求，独立调用有助于分离职责，但仍可能共同漏判，不承诺事实性100%保证。现有资料量很小，无需新增联网检索、向量数据库或知识图谱。对更强确定性要求，可另选“事实句从素材原文拼装、创意从受控模板选择”的严格模式；它牺牲表达自由，不作为本轮默认推荐。

| Case | 独立预期 |

| F05 审核缺项、假引用、uncertain、故障 | 不生成合格脚本、不保存；内容与技术错误分开记录 |
| F06 首次不合格、修正后合格 | 模型收到具体问题并调整；素材保留；failed与succeeded分别存在，最终只保存一份 |
| F07 持续不合格 | 达到界限后incomplete，解释原因，plan0行，不能把删除审核步骤当成功 |
| F08 篡改/旧审核/版本变化 | 审核结论不能用于另一份文本、素材或策略版本，不能绕过保存校验 |
| F09 原题目回归 | 预算/期限/12→8重规划、失败保留、重复执行保持；纯换档位时仅在绑定仍有效下复用脚本审核 |

语义审核器用独立标注的正反例报告误放行（无依据内容被接受）与误拦截（有依据内容被拒绝），不以审核器自己说passed作为金标准。程序流程用Fake/MockTransport和真实SQLite离线验证；后续真实评测由独立逐条素材核对判定，保留所有失败、审核用量和实际Trace。
