# 需求、范围与成功标准

## 用户与目标

用户为内容运营人员。给定活动主题、预算和截止时间，形成一份可保存、可审查的短视频活动方案，包含脚本草稿、费用、预计工期与执行记录。项目只规划；方案保存不代表真实视频已经制作、审核或发布。

输入主题可自由描述；当前合成资料只覆盖“影芽剪辑”的字幕、裁剪拼接等主题。资料不足时说明缺口，不编造素材。

## 输入、材料与交付

| 项目 | 内容 |
|---|---|
| 必要输入 | 主题、正整数模拟预算、明确截止时间；结构化入口还需request_id |
| 自然语言入口 | 收集/修改三项字段、追问、展示摘要，用户确认后生成稳定Request |
| 合成资料 | [素材](../src/content_planner/data/materials.json)、[报价](../src/content_planner/data/pricing.json)、[别名](../src/content_planner/data/aliases.json) |
| 可调用能力 | 素材检索、脚本生成、成本与耗时估算、方案保存；另有修订/停止控制动作 |
| 成功输出 | 已保存方案与plan_id、四项未来活动、脚本及来源、费用合计、真实执行步骤、工具结果、Trace |
| 非成功输出 | needs_input或incomplete、缺失字段/错误/缺口、已完成和失败的真实尝试 |

自然语言草稿仅存当前进程，需求抽取可产生API调用；确认前不创建业务任务。原结构化入口缺信息时不调用业务模型。需求收集与自由对话体验的边界见[方案](02-solution.md)。

## 领域定义

| 名称 | 含义 |
|---|---|
| request | 同一request_id标识的已确认需求，预算和截止时间不可由模型放宽 |
| candidate / revision | 模型选择的素材、创意简述和档位组成的一版候选 |
| attempt | 某动作的一次尝试；后续成功不能覆盖原失败 |
| script draft | 根据所选素材生成的文本草稿，不是视频成品 |
| estimate | 程序计算的分项费用、工期、可行性及缺口 |
| saved plan / completed | SQLite已提交的方案；未来活动仍为planned |

## 预算与工期的唯一口径

```text
total_units = 素材费 + 脚本定稿费 + 剪辑档位费 + 审核费
total_minutes = 素材准备 + 脚本定稿 + 剪辑 + 审核的串行分钟
estimated_finish_at = 本次读取的当前时刻 + total_minutes
可保存 = 费用不超过预算，并且预计结束不晚于截止时间
```

报价基线pricing-v1：M01/M02各1单位/10分钟；脚本2/20；basic剪辑4/45、premium剪辑8/90；审核1/15。basic合计8单位/90分钟，premium合计12单位/135分钟。值从资料读取，业务程序没有“超预算自动改basic”的决策分支。

预算采用正整数模拟单位，不接受小数或货币换算。重试/改稿不累计为方案费用；API真实费用单独记录，未知为null。四项活动按串行工期相加，不模拟并行资源或工作日。结构化时间为带UTC偏移的ISO 8601，内部归一UTC、展示UTC+08；过去或等于当前时刻的截止时间拒绝，预计结束恰好等于deadline允许。保存前重新读取时间，不能用过期估算绕过期限。

## 功能需求与验收

| ID | 要求 | 可观察的成功标准 |
|---|---|---|
| R01 | 输入校验 | 缺预算/截止时间/主题准确列出缺项；原结构化入口零业务模型调用、无业务任务 |
| R02 | 素材检索 | 返回存在的合成素材、事实、版本与费用；无命中如实返回空 |
| R03 | 脚本生成 | 标题、hook、body、cta及来源满足契约；失败不生成成功产物 |
| R04 | 费用与工期 | 程序计算分项、合计与预算/期限缺口，保存时重验 |
| R05 | 模型闭环 | 模型选择动作→工具执行→真实观察→模型调整或结束 |
| R06 | 正常完成 | 约束满足且实际plan事务提交，输出completed及唯一plan_id |
| R07 | 工具失败 | 错误返回模型，由模型决定重试/停止；原failed和成功结果保留 |
| R08 | 超预算/超期 | 调整候选后重估；不放宽用户约束；无解返回未完成与已评估缺口 |
| R09 | 重复执行 | 同ID同输入只读；不同输入报冲突；最多一份已保存方案 |
| R10 | 有界运行 | 最多32次业务模型尝试、24次工具/控制动作、4版候选；达到上限明确未完成 |
| R11 | 显式续跑 | 复用仍有效产物、保留失败记录及累计限额，不自动重置任务 |
| R12 | 可观察 | Trace包含参数、结果摘要、公开动作理由、状态和下一决策关联 |
| R13 | 离线运行 | 无密钥可运行标记清楚的Mock，普通pytest禁网络 |
| R14 | 可审查证据 | 至少正常、信息不足、工具失败三类实际记录，且覆盖全部必验要求 |
| R15 | 宿主无关 | 公开依赖与可移植路径；无Codex的Windows安装和离线运行有证据 |

五项必验为正常、缺预算/截止时间、工具失败、预算超限、重复执行；R11为已实现的加分范围。需求、测试与真实案例对应关系见[评估](03-evaluation.md)及[案例索引](../examples/README.md)。

## 输出分层

`execution_steps`记录Agent实际动作与各次尝试；`tool_results`保留返回值/错误；`task_plan`是成功方案的四项未来活动，均为planned。没有有效估算时total_units为null；没有提交plan时saved_plan为null。needs_input、incomplete和completed分别表示需补输入、任务未完成和方案已保存。

## 边界与非目标

单请求选择一项主素材、一份脚本、一个制作档位；默认受众为新手创作者、平台为短视频平台，不额外索取无关必填信息。不做视频制作、外部发布、支付、互联网素材抓取、多Agent协作或分布式调度。不承诺任意文本事实检查、最优方案或API exactly-once。

内容应受素材事实约束；当前程序有来源/结构及明确禁止表述校验，没有独立语义审核器。本轮核心评测将营销扩写单列质量备注，不用它否决预算/状态/重规划场景，历史严格内容结论保留。自然语言入口已支持字段收集和确认，运行中任务的自由对话修改尚未实现。

实际核心20例与离线408项已通过，详见[最新结果](03-evaluation.md)。Linux和其他未测范围不能由这些结果推断通过。
