# 分阶段开发与验收计划

更新日期：2026-10-29。项目根目录为用户指定的xiaoying；目标仓库为 https://github.com/yysk6/xiaoying 。

用户要求：分阶段开发、分阶段验收，开发使用karpathy-guidelines。本轮只更新计划，不继续安装、业务编码或模型调用。

执行更新：用户现已授权S0；仅开展S0范围，真实状态与证据以docs/stages/S0.md为准。S1及以后仍待授权和验收。上句“本轮只更新计划”描述此前规划轮次，不限制现已明确授权的S0。

## 1. 阶段执行规则

SDD指规格驱动开发，TDD指测试驱动开发，不额外引入方法论平台。每次只实现一个已获准阶段，不提前搭建后续业务代码、通用接口或扩展能力。

1. 明确范围：列出需求编号、可观察行为、边界、错误及本阶段不做的内容。规格冲突先修文档；无法从题目或已定规格推导的产品选择才向用户确认。
2. Red：先写行为测试，运行并保留真实失败。导入失败只证明缺模块，不代表预算或状态行为已被验证。
3. Green：仅实现使目标测试通过的最小代码，不为未来扩展创建通用框架。
4. Refactor：在测试保护下整理本阶段代码，不混入无关重构。
5. 自验：运行目标测试及必要回归，核对实际输出和失败路径，更新结果及限制。
6. 交付：提供验收包，标为ready_for_review，停止推进。
7. 收到用户明确验收通过后才标为accepted，进入下一阶段；要求修改时只修当前阶段及受影响规格和测试。

第7步来自用户的分阶段验收要求，不是技能额外增加的审批流程。用户可以明确授权连续执行几个阶段；未授权时不跨阶段。

## 4. 各阶段具体边界

### S0：工程与依赖基线

检查已有.venv和中断安装；验证候选依赖后生成运行/开发锁文件；建立最小可安装包与离线测试入口；执行独立LangGraph/SQLite恢复探针。最小包只含包标识，不实现业务命令、工具或Agent。

验收覆盖依赖一致性、tests/unit/test_environment.py及从锁文件重建环境。checkpoint探针的预期：节点一成功、节点二失败、重建图后从节点二继续，节点一仅调用一次。这不等同业务续跑已通过。

配置remote并核对远端历史，禁止覆盖未知远端、强推或自动合并冲突。外部Git权限/认证与本地阶段验收分开记录；不阻止离线工作，但未同步不能称为最终交付。S0不调用付费模型。

### S1：契约与领域规则

实现所需Pydantic DTO、标准化输入、可注入Clock、稳定指纹、报价函数和脚本校验。时间统一UTC；浮点预算即使是10.0也拒绝；费用/完成时间恰等预算/截止时间视为满足。

验收覆盖缺参数、非法参数、时区等价、basic=8 units/90分钟、premium=12 units/135分钟、缺口、错误source_id及无依据百分比。禁止硬编码“预算10就选basic”。不接数据库、CLI、模型HTTP或业务图。

### S2：合成资料与本地工具

实现包内资料定位、版本化数据、明确的匹配和排序、候选修订、脚本生成接口与确定性估算。注入Fake生成器，其余是实际本地函数。

验收覆盖空检索/改写命中、未见素材、旧revision、换档位复用脚本但废弃估算、换素材/brief使旧脚本失效，以及feasible=false仍是成功估算。不接真实API、不实现自主循环或保存方案。

### S3：存储与保存幂等

用真实临时SQLite验证请求注册、冲突、事件和方案保存。保存前复核当前依赖与硬约束；保存方案和成功事件在同一事务提交；唯一约束保证一请求一终版。

必须检查实际行数、注入提交前失败、核对已提交事实，不能Mock保存函数。这里只证明存储事实，不宣称跨进程checkpoint恢复通过。不接模型/CLI，不引入ORM或消息队列。

### S4：离线Agent循环

LangGraph只连接decide/dispatch；Fake ModelClient给出可检查的动作序列；业务工具、状态和数据库使用实际实现。验证12->8修订、失败观察后的下一动作、成功结果保留、旧估算拒绝及限额。

Fake动作是显式测试输入，不是智能效果证据。程序可拒绝不合法动作，不能自己决定超预算后选basic或失败后自动重试。不接真实API，不实现多Agent、通用DAG或跨进程业务恢复。

### S5：CLI与核心案例

实现run/show与结果和Trace导出，贯通正常、缺信息、工具失败、预算/期限不足、重复提交和导出失败。README提供已经实测的离线命令。

至少保存正常、缺信息、工具失败三组实际输入/输出/Trace，再补超预算修订和重复执行。逐项核对状态、费用和数据库。通过只代表离线核心版通过；resume尚不开放为可用功能，不做空实现。

### S6：显式失败续跑

完成resume与业务checkpoint恢复；用新进程验证，不仅在同一函数内重复调用。核对manifest与已提交方案，复用已持久化且有效的产物，保留失败历史和累计额度。

验收包括生成失败后继续、候选变化的失效、保存提交后checkpoint前崩溃、资料变化拒绝恢复和额度不足。外部模型返回但未持久化可能重复付费，不承诺API exactly-once。

### S7：真实模型接入与效果

先用HTTPX假传输验证参数、消息配对、JSON和401/429/5xx/超时映射，再从环境变量读取密钥，运行指定模型工具探针及真实案例。普通单测保持零付费、零网络。

缺有效配置时明确外部阻塞，不能标记S7通过；密钥不写入代码、测试、命令日志或提交。至少保留正常和根据工具失败调整动作的真实路径；直接选对低价方案不能写成超预算后修正。L04固定状态评估单独标注setup来源。

真实探针由原计划S0调整到S7，避免离线阶段受密钥配置阻塞。若需要提前验证，须由用户明确授权该跨阶段探针，不默认执行。

### S8：可移植性与最终交付

从公开锁文件干净安装；验证包内资源、非仓库cwd运行、Windows/Linux离线行为；不依赖Codex插件/MCP/账户/缓存/专用命令。

更新评估、AI使用、复盘、实际用时、全部验收状态；检查密钥和隐私后同步指定GitHub，核对远端最终commit。未运行的平台或未完成的同步如实记录。全部R01—R15通过才标记完整项目完成；不临时增加界面、部署或多Agent。

## 5. 每阶段验收包

报告路径为docs/stages/S<N>.md，证据为examples/tests/stages/S<N>/。本轮只定义路径，不创建空报告冒充完成。

每份报告必须包含：

- 状态：planned / in_progress / ready_for_review / accepted / blocked。
- 范围：需求、Case断言及本阶段未覆盖项。
- 变更：实际文件、设计取舍。
- Red：真实失败命令、失败原因、结果路径。
- Green：真实通过命令、退出码、结果路径。
- 演示：输入、输出、存储和Trace核对方法。
- 限制：外部阻塞、未验证行为、是否影响验收。
- 版本：本地commit、远端同步状态。
- 验收记录：用户明确通过/要求修改及日期。

ready_for_review不等于accepted；blocked不抹掉已有成果；静态Schema检查不是业务测试；Fake通过不是真实模型通过。每阶段结束报告未解决项并等待验收，不顺带实现下一阶段。

## 6. 变更、回归与时间

需求 -> 契约/状态 -> 测试断言 -> 最小实现 -> 证据 -> 验收。修改硬约束、幂等键、模型ID或状态定义须先更新ADR与相关测试。

开发时运行当前目标测试，公共契约/状态/存储变更时运行已通过阶段的必要回归。尚未实现阶段的测试不算当前阶段的验收项；报告写明选择范围，不把跳过当通过。

每阶段以本地commit区分，远端认证失败单独记录，不强推或覆盖历史。后续发现旧阶段缺陷，补回归测试修复，不改写历史验收结果。

不承诺九阶段能在3小时全部完成。记录调研、规格、编码、测试、验收与修复的实际用时；题目建议投入与实际投入分开。

本轮只交付阶段规划。下一次开发只执行S0，结束于S0验收包，不自动实现S1。
