# 复盘记录

当前为设计阶段，尚无实现后的学习结论和性能/效果数据。以下是已识别的设计难点，不能冒充开发复盘。

## 设计阶段的主要取舍

- 预算采用最终方案模拟报价，与实际API调用成本分开，避免重规划时混淆费用口径。
- 使用LangGraph承担checkpoint，业务仍负责保存幂等和产物有效性，避免把框架能力等同业务正确性。
- 区分Agent执行步骤与未来活动步骤，避免脚本生成后把视频制作/发布误标完成。
- 真实模型可能预先选对低价方案；不制造虚假的超预算轨迹，单独标识给定状态的决策评估。
- 对模型调用只承诺已持久化结果的复用，不宣称崩溃边界下exactly-once或生产级Runtime。

## 实现后必须填写

1. 最难的实际问题：触发输入、预期、错误结果、根因及修复commit。
2. 学习到的具体知识：与原先理解不同之处，以及用什么测试确认。
3. 一次模型失败或不理想决策：原Trace、改进方式、改进后的实际结果；没有改进成功也如实记录。
4. 实际用时：调研、规格、编码、测试、文档分别统计，包含AI协作时间。
5. 未完成项和限制：明确影响哪些验收点；不能只写“继续优化”。
6. 下一步：最多三项，按已观察问题排序，不把未验证的高级功能列作成绩。
