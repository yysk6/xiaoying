# 需求规格

## 用户与目标

用户是运营人员。输入活动主题、模拟预算、明确截止时间；系统产出一条短视频的活动执行方案、脚本草稿、费用与预计工期，保存为可查看的本地方案。系统只规划，不执行制作或发布。

主题是用户自由输入；首版资料库只支持合成产品“影芽剪辑”的素材主题。资料外主题须说明缺口，不能伪造素材。

N1—N3授权新增自然语言终端：按[入口方案](../../10-natural-language-intake-plan.md)及[输入契约](../../06-contracts.md)收集/追问/展示三项需求，明确确认后才启动业务；request_id由程序生成。原结构化CLI和显式JSON交互仍可由用户提供ID。需求理解可产生独立API用量，未确认不创建业务任务；草稿只存当前进程。实际效果与限制见[N3报告](../../stages/N3.md)，不把入口开发完成视为内容事实性通过。

## 领域定义

| 名称 | 确定含义 |
|---|---|
| request | 一次已确认的业务需求；由 request_id 标识（自然入口生成、结构化入口由用户提供），预算和截止时间是硬约束 |
| attempt | 对同一工具的一次执行尝试，失败记录不会被后续成功覆盖 |
| candidate/revision | 模型提出的一版候选方案，改变素材、创意简述或制作档位会产生新版本 |
| script draft | 模型从合成素材生成的文本草稿；不是视频成品 |
| estimate | 程序根据候选、脚本和报价表算出的报价、工期与约束结果 |
| saved plan | 已通过检查并提交到 SQLite 的方案，最多一份/request |
| completed | 本地方案保存成功；不代表真实活动或视频执行完成 |

## 预算与工期的唯一口径

模拟费用单位为整数 `unit`，`budget_units` 必须为正整数，首版不接受小数或货币换算。所有费用非负；最终报价为：

```text
total_units = 所选素材费 + 脚本定稿费 + 所选剪辑档位费 + 审核费
total_minutes = 素材准备分钟 + 脚本定稿分钟 + 剪辑分钟 + 审核分钟
estimated_finish_at = 保存前重新读取的当前时间 + total_minutes
可保存 = total_units <= budget_units 且 estimated_finish_at <= deadline_at
```

四项活动串行执行，不模拟资源冲突、工作日和并行制作。截止时间必须为带 UTC 偏移的 ISO 8601，内部转 UTC，展示使用北京时间 UTC+08:00。截止时间已经过去则输入无效；恰好在截止时间完成视为满足。

费用表表示最终方案的预计报价，不模拟扣款、采购或每次工具重试收费。模型 API 的 token 用量只记运行指标；没有提供可核对价格数据时，真实费用为 `null`，不能假装为 0。

固定报价基线（版本 `pricing-v1`）：素材 M01/M02 各 1 unit、10 分钟；脚本定稿 2 units、20 分钟；basic 剪辑 4 units、45 分钟；premium 剪辑 8 units、90 分钟；审核 1 unit、15 分钟。因此 basic=8 units/90 分钟，premium=12 units/135 分钟。实际值从数据文件读取，业务代码禁止硬编码“12 改 8”。

## 功能需求与验收

| ID | 要求 | 可验收条件 |
|---|---|---|
| R01 | 输入校验 | 缺主题、预算、截止时间时列出缺失字段，不调用模型，不保存方案；格式非法分别报告 |
| R02 | 素材检索 | 返回真实存在的合成素材、版本、事实和费用；未命中返回空数组，不能造数据 |
| R03 | 脚本生成 | 产出标题、开头、正文、行动引导及素材来源；生成失败为失败状态 |
| R04 | 费用与工期 | 由确定性代码计算分项、合计、超预算缺口、超期分钟；模型不能填写或覆盖合计 |
| R05 | 模型闭环 | 真实模型选择工具，观察结果后决定重查、改候选、重试、保存或停止 |
| R06 | 正常完成 | 约束通过且数据库保存成功，输出方案和 plan_id，状态 completed |
| R07 | 工具失败 | 失败结果返回模型；可由模型决定一次重试或停止；保留此前已成功且仍有效的结果 |
| R08 | 超预算/超期 | 模型可调整档位或素材后重新估算；不能自动放宽硬约束；无可行结果时报告已评估候选和缺口 |
| R09 | 重复执行 | 相同 ID/相同输入的 run 只读取已有任务或方案；同 ID/不同输入报冲突；方案唯一 |
| R10 | 明确停止 | 达到请求/动作/候选上限，返回 incomplete 和具体原因；禁止无限重试 |
| R11 | 持久化与续跑 | 显式 resume 从 checkpoint 恢复；已完成且未失效的步骤不重复执行；不重置累计限额 |
| R12 | 可观察 | 输出步骤、参数、返回摘要、简要动作依据、状态与下一动作关联；不导出内部推理 |
| R13 | 离线入口 | 无密钥可跑明确标记为 mock 的案例；普通测试默认不联网 |
| R14 | 证据与交付 | 至少三类实际案例及两条真实模型执行路径；测试结果与对应 Trace 可追溯 |
| R15 | 宿主无关与可移植 | 不依赖Codex内部插件/MCP/账户/目录；公开依赖可安装；无Codex的干净环境可执行离线CLI和测试 |

R01—R10、R12—R14 覆盖统一规范与题目验收；R11 是本项目主动选择的加分范围，不以它取代必做案例；R15是用户补充的明确要求。

## 输出分层

- `task_plan`：四个未来活动步骤，状态均为 `planned`。不能将视频制作/审核标为成功。
- `execution_steps`：Agent 已执行的检索、草稿生成、估算、保存及各次尝试的真实状态。
- `tool_results`：对应真实结果/错误的引用，保留部分成功结果。
- `total_units`：当前候选最新有效估算；没有有效估算则为 null。
- `saved_plan`：仅保存成功时包含 plan_id 和内容；其他情况为 null。
- `status/reason/missing_fields`：明确的完成、待补充或未完成原因。

## 边界与非目标

单请求只选择一项主素材、一个脚本草稿、一个剪辑档位；不生成多条视频或跨平台投放组合。默认受众为“新手创作者”，平台为“短视频平台”，二者作为明确的首版业务默认，不作为额外必填信息。生成内容不得宣称没有素材支持的产品效果。

不自动采购、不真实发布、不执行付费业务工具、不保证文本事实检查覆盖全部语义错误、不保证最优方案。无可行结果只意味着当前合成资料与已评估候选中没有找到满足约束的方案。

实现质量门槛：所有确定性验收测试通过；真实模型至少展示“正常保存”与“工具结果导致动作改变”两条路径；没有实际运行结果时不得宣称完成验收。
