# 复盘记录

S0—S2已有工程、领域及本地工具的自验记录，用户验收分别记录。尚无真实模型性能或效果数据；以下设计取舍与实际实现复盘分开列出。

## 设计阶段的主要取舍

- 预算采用最终方案模拟报价，与实际API调用成本分开，避免重规划时混淆费用口径。
- 使用LangGraph承担checkpoint，业务仍负责保存幂等和产物有效性，避免把框架能力等同业务正确性。
- 区分Agent执行步骤与未来活动步骤，避免脚本生成后把视频制作/发布误标完成。
- 真实模型可能预先选对低价方案；不制造虚假的超预算轨迹，单独标识给定状态的决策评估。
- 对模型调用只承诺已持久化结果的复用，不宣称崩溃边界下exactly-once或生产级Runtime。

## 实现后必须填写

### S1实际观察（2026-10-29）

- 契约一致性检查发现：将BeforeValidator别名再叠加Field(pattern=...)时，本次Pydantic组合的运行校验会拒绝非法值，但导出的Schema丢失pattern。改为标量field_validator与素材ID内部注解，两个Schema语义对照测试通过。该修正随S1提交，可用`git log -1 -- src/content_planner/contracts.py`定位。
- Python的fromisoformat会规范化不合法的偏移分钟，例如+01:99；输入边界必须拒绝这种值。预算严格类型、UTC归一与Clock相关检查分别验证，避免把系统当前时间混入结构解析。
- 期限缺口用timedelta整数除法实现向上取整，测试覆盖超出1微秒、60秒、60秒加1微秒；金额与期限恰好满足的边界也已验证。
- 代码只对外部输入、模型脚本和规格要求的事实规则校验；报价与指纹函数接收可信完整数据。没有补通用重试、缓存引擎或下一阶段接口。
- 该阶段交付时未验证：任意自然语言事实、实际模型决策、业务保存/续跑和Linux；S2随后获明确授权，记录如下。

### S2实际观察（2026-10-29）

- 单次报价中若对当前/替代档位各读一次Clock，比较会混入时间差。递增Clock测试先失败，最小修正为读取一次时刻后共同计算；下一次显式估算仍重新读取。
- 只冻结Catalog外层不能隔离内部列表和报价DTO的外部修改。公开入口测试复现facts被清空，LocalTools构造时复制一次已验证快照，避免文件哈希与实际任务数据偏离；没有逐动作重读或通用缓存框架。
- Spec审查发现Literal[True]在严格模式仍接受1/1.0；补真实加载Red后加明确布尔true校验。两轴审查与修复记录见[S2审查](../../stages/S2-review.md)。
- 全部56项S2测试使用真实资料/工具，只替换模型与时间边界。显式演示的12→8来自调用方选择档位，不能作为模型重规划成绩。
- 全量171项在开发环境和正式wheel干净环境均通过。真实API、保存、Agent决策、跨进程业务恢复及Linux仍未验证；S3等待授权。

### S2开发效率反思（2026-10-29，用户反馈）

用户指出全程开发有太多多余工作，导致耗时过长。执行中的主要浪费是：将缺模块/方法也拆成独立轮次；21轮Red/Green配套约100个证据文件；审查结束前提前验证wheel，修正后再次验证；多个文档重复维护状态；为单次记录、汇总和检查投入辅助脚本。必要验证本身有价值，但执行过碎、材料重复，挤占了业务开发时间。

根因是把遵循规则等同于增加流程和材料，偏离karpathy-guidelines的最小充分原则。后续执行方式统一见[开发效率约定](../../08-development-plan.md#开发效率约定s2复盘后生效)：收敛切片、证据、重复验证、文档和辅助工具；既有验收事实与历史证据保留。此次仅调整开发方式，S2用户验收仍pending，S3仍等待授权。
